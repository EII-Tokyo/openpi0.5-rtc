# Phase 67 Replay Requires Calibrated Table Gate

## Question

Phase 65 and Phase 66 made table-to-base calibration explicit, but the replay validator still allowed a diagnostic table config to be used accidentally.

Phase 67 asks:

Can final replay validation explicitly refuse diagnostic or not-calibrated table-frame configs before starting Isaac?

## Implementation

Updated script:

```text
aloha_isaac_replay/scripts/validate_aloha1_gripper_passive_contact.py
```

New option:

```text
--require-calibrated-table-frame
```

When this option is set, the script requires:

```text
--support-plane-config <calibrated config>
```

Then it calls:

```text
aloha_isaac_replay/scripts/audit_table_frame_candidate.py
```

before starting Isaac.

The replay script proceeds only if the audit returns:

```text
PASS_TABLE_TO_BASE_CALIBRATION_READY
```

## Diagnostic Config Is Rejected

This command is expected to fail:

```text
.venv/bin/python aloha_isaac_replay/scripts/validate_aloha1_gripper_passive_contact.py \
  --support-plane-config examples/aloha_isaac/config/phase63_fixed_table_candidate.yaml \
  --require-calibrated-table-frame
```

Reason:

```text
T_world_table is diagnostic, not calibrated
T_table_left_base or T_table_right_base is missing/not calibrated
```

The failure happens before Isaac startup, which is the desired behavior.

## Measured Config Is Accepted

A config generated by:

```text
aloha_isaac_replay/scripts/create_table_to_base_calibration.py
```

can be accepted if the measured transforms pass the Phase65 audit.

The measured file must contain:

```text
T_world_table
T_table_left_base
T_table_right_base
```

with calibrated status and valid Isaac/USD quaternions.

## Why This Matters

The replay validator now has two modes:

| Mode | Behavior |
| --- | --- |
| diagnostic replay | can use Phase63 fixed table candidate for local debugging |
| calibrated replay | must pass Phase65 table-to-base audit before Isaac starts |

This keeps old diagnostic experiments reproducible while preventing them from being silently promoted into final workcell validation.

## Validation

Validated:

```text
python py_compile
pytest
CLI diagnostic-config rejection
```

The CLI rejection returns a normal argparse error, not a traceback.

No real robot or `192.168.1.103` action was used in this phase.
