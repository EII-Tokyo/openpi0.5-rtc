# ALOHA1 Home–Sleep Digital-Twin Correspondence Design

**Date:** 2026-08-03

**Status:** USER_APPROVED_DESIGN

**Hardware scope:** Stationary ALOHA 1 follower, Interbotix ViperX-300 6DOF / `aloha_vx300s`

**First execution scope:** `follower_left` arm only; `follower_right` and both grippers remain stationary

## 1. Objective

Close Task 8 without promoting either optimization candidate, then establish the first real-versus-digital ALOHA correspondence experiment. The experiment sends one hash-frozen Home–Sleep command stream first to the Isaac Sim digital follower and, only after the digital safety gate passes and the user separately authorizes real motion, to the real `follower_left`.

The formal trajectory is three uninterrupted cycles:

```text
Home hold
Cycle 1: Home -> Sleep -> Home
Cycle 2: Home -> Sleep -> Home
Cycle 3: Home -> Sleep -> Home
Final Home hold
```

The test validates command identity, joint semantics, endpoint correspondence, repeatability, and measured dynamic differences. It does not assume that real and simulated samples must be numerically identical, and it does not claim a calibrated physical digital twin merely because both systems reach the named poses.

## 3. Official Pose and Command Sources

The experiment uses exact-model, pinned official sources rather than inferred poses.

### 3.1 Home pose

The pinned official Interbotix ALOHA `robot_utils.py` defines the Stationary ALOHA follower Home arm pose as:

```text
[0.0, -0.96, 1.16, 0.0, -0.3, 0.0] rad
```

Source:

- repository: `https://github.com/Interbotix/aloha.git`;
- commit: `4fa6b2c4428f5334441a7bee5ab2b2e8071cff93`;
- file: `aloha/robot_utils.py`;
- license: MIT;
- frozen local evidence: `.codex/artifacts/20260802-aloha1-official-model-first/sources/official_repo_probe/interbotix_aloha_main/aloha/robot_utils.py`.

### 3.2 Sleep pose

The pinned exact-model `aloha_vx300s.yaml` defines:

```text
joint_order:
  [waist, shoulder, elbow, forearm_roll, wrist_angle, wrist_rotate, gripper]
sleep_positions:
  [0.0, -2.05, 1.7, 0.0, -2.0, 0.0, 0.0]
```

Only the first six arm values enter this experiment. The gripper value is not commanded.

Source:

- commit: `b66d5b905725351dd71d3251a06cd3f4c777940f`;

The generic `vx300s.yaml` sleep pose is explicitly not substituted for the ALOHA-specific pose.

### 3.3 Motion semantics

Official `sleep_arms()` first commands Home and then the exact-model Sleep pose. It uses `move_arms()` with a default `moving_time=5.0 s`. The pinned ALOHA constants define `DT=0.02 s`, and `move_arms()` sends non-blocking position targets generated by `numpy.linspace` at that cadence.

The Trossen X-Series Python-ROS documentation recommends leaving Sleep through Home and returning through Home before Sleep. The ALOHA shutdown documentation requires the follower arms to reach their staged/sleep configurations before shutdown.

## 4. Frozen Experiment Identity

One machine-readable command manifest is the only command authority for both environments. It records:

- experiment ID and schema version;
- exact robot product and role;
- robot name `follower_left`;
- explicit six-joint order;
- units and sign/offset mapping;
- Home and Sleep vectors;
- source repository, commit, license, local path, and SHA-256;
- command rate and rational scheduler definition;
- segment boundaries and cycle number;
- every commanded joint vector;
- expected stationary robots and joints;
- digital Stage path/hash and diagnostic layers;
- forbidden attachment/constraint mechanisms;
- manifest SHA-256.

The manifest sequence is:

- initial Home hold: 50 samples;
- each movement segment: 250 samples at 50 Hz;
- each Sleep or Home endpoint hold: 50 samples;
- three cycles, six movement segments;
- total command samples: `50 + 3 * (250 + 50 + 250 + 50) = 1850`;
- nominal duration: 37 seconds.

Both runners consume the stored samples. They may not independently recompute Home, Sleep, interpolation, order, timing, or signs.

## 5. Digital Qualification

### 5.1 Runtime boundary

Digital qualification uses a fresh, independent Isaac Sim process and does not operate a user-open GUI. It is restricted to:

- Isaac Sim 5.1.0.0;
- Kit 107.3.3;
- PhysX 107.3.26;
- the frozen fidelity/full-body-collider Stage, not the rejected throughput candidate;
- the exact source-limit finger session layer where required;
- existing physical and controller parameters without tuning.

The current candidate input is:

```text
assets/Trossen/ALOHA1/1.0/diagnostics/
cad_derived_full_body_colliders/1.0/
aloha1_cad_derived_full_body_collider_gripper_decomposition_tabletop_zero_z_up_meters_diagnostic.usda
```

Its currently recorded SHA-256 is `327361d291b13a316fe3390e2add54c1d76ed6c2393455970a6e59f954eb9bb9`. Implementation must re-read the path, hash, default prim, sublayers, references, and required prims before use; an old hash is not sufficient authorization to switch a Stage.

### 5.2 Scheduling

The existing 60 Hz physics frequency is unchanged. A rational 50 Hz command scheduler applies manifest targets and holds the last target between command ticks. It must not use accumulated binary floating-point time to decide command boundaries. Each telemetry record includes the nominal command time, actual application physics frame/time, and scheduler phase error.

### 5.3 Preconditions

Before motion:

- verify one `follower_left` and one stationary `follower_right` articulation;
- verify DOF names/order and the explicit joint map;
- verify Home target/readback and first-frame stability;
- verify finite limits, velocity, force, and drive readback;
- verify gripper targets remain fixed and legal;
- verify full-body colliders and the table/frame composition;
- verify initial contact/overlap state;
- verify no forbidden fixed joint, SurfaceGripper, or parent attachment;
- verify source/final/default asset hashes remain unchanged.

### 5.4 Telemetry

Every physics frame records:

- physics frame, physics time, and exact `dt`;
- manifest command index and cycle/segment;
- nominal command time and actual application time;
- target, controller-applied target, readback, velocity, and target error for all arm DOFs;
- effort/force/current only when the local Isaac 5.1 API provides a verified meaning;
- end-effector world pose;
- `follower_right` and gripper readback;
- contact pair paths, position, normal, impulse, separation, and penetration;
- Home/Sleep arrival and hold state;
- deterministic signature inputs.

### 5.5 Digital gate

Digital qualification is `PASS` only if:

1. all three cycles complete without reset;
2. every joint direction agrees with the frozen mapping;
3. all targets and readbacks are finite and legal;
4. `follower_right` and both grippers have no unintended command or motion;
5. there is no dangerous robot/environment, cross-follower, or non-adjacent self-contact;
6. contact-envelope-only records are separated from impulse-carrying physical contacts;
7. no persistent penetration, tunneling, or numerical ejection occurs;
8. all Home/Sleep endpoints are reached and held reproducibly;
9. the final state is Home;
10. the command manifest, Stage, source, and final/default hashes are unchanged.

Because this trajectory is a real-motion prerequisite rather than a grasp task, any impulse-carrying robot/table or robot/frame contact blocks real execution until separately reviewed. The prior policy that finger/table contact is not automatically a grasp failure does not authorize contact during this Home–Sleep safety qualification.

Endpoint and trajectory numeric tolerances must be derived and frozen before formal execution from exact-model encoder/controller resolution and the local Isaac readback baseline. No tolerance may be selected from a result that it is intended to judge.

### 5.6 Visual evidence

The complete digital test is recorded with the whole follower arm visible. Evidence includes:

- normal full-arm video;
- full-arm collision-visualization video;
- raw and annotated Home, first Sleep, first returned Home, third Sleep, and final Home frames;
- annotations for active robot, cycle, command index, target/readback, Stage/hash, contact state, and PASS/FAIL;
- visual-model review of every retained key image and both videos.

If a reproducible anomaly occurs, retain before-anomaly, first-anomaly, and final-failure frames and identify the offending link, expected collider, observed contact/penetration, and matching telemetry. The test is not rerun with changed physics parameters to hide the failure.

## 6. Real-Robot Read-Only Preflight

Passing the digital gate does not authorize access to or motion of the real robot. Before accessing `192.168.1.103`, obtain explicit user authorization for that access. The read-only preflight then verifies:

- project path `/home/eii/openpi0.5-rtc-reward-learning`;
- exact Stationary ALOHA `follower_left / aloha_vx300s` identity;
- ROS namespace, six-joint order, and exact-model configuration;
- expected serial alias and absence of competing bus owners;
- no DYNAMIXEL Wizard or second controller holding the bus;
- operating mode, torque state, voltage, temperature, and hardware-error status;
- joint limits and current joint readback;
- joint-state publication cadence and timestamp reliability;
- `follower_right` and gripper exclusion;
- available stop/abort mechanism.

Preflight performs no motion and produces a machine-readable report. A failed preflight blocks motion without modifying robot configuration.

The physical workspace must be clear, the whole arm must be visible to the operator, and an immediate stop mechanism must be available. The experiment must not run unattended.

## 7. Real Execution Authorization and Runner

The real runner defaults to `DRY_RUN`. Motion requires all of:

- a digital qualification `PASS` bound to the same manifest hash;
- a real preflight `PASS`;
- exact `follower_left` selection;
- an `--execute-real` gate;
- the expected manifest SHA-256 supplied explicitly;
- a same-turn explicit user authorization for real motion;
- operator confirmation that the workspace is clear and stop control is ready.

The real controller consumes the same 1850 stored command samples. It does not call an independent convenience function that could generate a different trajectory. It records command index, send time, ROS processing time when observable, readback, velocity, current/effort when officially defined, hardware status, late or missing messages, endpoint state, and abort reason.

Immediate abort conditions include:

- hardware error or communication loss;
- non-finite or missing readback;
- an actual joint moving opposite the commanded direction;
- joint-limit violation or unsafe limit proximity;
- contact with an obstacle or unplanned physical resistance;
- unintended `follower_right` or gripper motion;
- operator/user stop request.

The real test is recorded from a fixed overview that contains the entire `follower_left`, not only the end effector.

## 8. Real–Digital Alignment

Raw real and digital telemetry remain immutable. Comparison aligns records by command index and monotonic timestamps, preserves original sampling, and also resamples Isaac telemetry to the 50 Hz command grid for direct plots.

For every joint, segment, and cycle, calculate:

- commanded direction and endpoint;
- start latency;
- rise and settling time;
- overshoot;
- endpoint and steady-state error;
- RMSE and maximum absolute position error;
- velocity difference;
- Home and Sleep repeatability;
- cumulative Home/Sleep residual drift;
- real-versus-digital phase lag.

The report has four independent gates:

1. `COMMAND_IDENTITY` — both systems consumed the same manifest;
2. `JOINT_SEMANTICS` — order, unit, sign, offset, and direction correspond;
3. `KINEMATIC_ENDPOINT_CORRESPONDENCE` — Home and Sleep endpoints correspond;
4. `DYNAMIC_TRAJECTORY_CORRESPONDENCE` — timing and transient response correspond within predeclared, source-backed limits.

The preferred first-stage success result is:

```text
KINEMATIC_AND_SIGNAL_DIGITAL_TWIN_PASS
DYNAMIC_CALIBRATION_PENDING
```

Other literal classifications are:

- `SIGNAL_MAPPING_FAILURE`;
- `KINEMATIC_ENDPOINT_MISMATCH`;
- `DYNAMIC_RESPONSE_MISMATCH`;
- `REAL_EXECUTION_ABORTED`;
- `INCONCLUSIVE`.

No Isaac parameter is changed during this first comparison. Calibration, if required, becomes a separate evidence-backed task based on the preserved real trace and official exact-model controller definitions.

## 11. Explicit Non-Goals

This design does not:

- control both followers in the first experiment;
- command either gripper;
- control a leader;
- perform grasping, insertion, camera calibration, ROS expansion, or reinforcement learning;
- tune Isaac physics from the first real trace;
- modify final/default USD, collider, material, mass, inertia, solver, timestep, or drive parameters;
- claim a fully calibrated dynamic or contact digital twin from endpoint agreement alone.
