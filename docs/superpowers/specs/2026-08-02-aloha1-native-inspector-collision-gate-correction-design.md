## Corrected Diagnosis

The previous gate produced a false `PASS` for three independent reasons:

1. It used `UsdGeom.BBoxCache` world bounds as live collision geometry. At the
   accepted posture this reported approximately `-15.215 mm`, while directly
   transformed vertices of the same visual and collision meshes were at
   approximately `+0.016 mm` and `-0.041 mm` relative to the tabletop.
2. It treated the presence of a PhysX contact-report header as physical
   contact. The first reported candidate still had approximately `+10.6 mm`
   separation and zero impulse, so it was only inside the contact-generation
   envelope.
3. It rejected geometry only after crossing below the tabletop bottom plus a
   tolerance. That rule could accept entry through almost the entire 15 mm
   tabletop thickness.

The current evidence also shows that the visual and collision finger meshes
contain the same 831 vertices under the same world transform. A real top-face
contact had a near-`+Z` normal and roughly `-0.05 mm` separation. Therefore the
fix is to correct measurement and exercise the native Inspector path, not to
inflate or relocate collision geometry.

## Selected Architecture

The corrected workflow has three isolated components.

### 1. Pure collision decision model

The pure gate receives measurements rather than USD objects. A trial includes:

- exact table/finger contact pairs;
- minimum signed separation for an exact table/finger pair;
- minimum directly transformed finger vertex height inside the tabletop XY
  footprint;
- maximum visual-to-collision vertex disagreement for each supplier-CAD
  finger;
- commanded and realized shoulder positions;
- persistent physical-contact step count;
- finite-state, joint-limit, CCD, unexpected-contact, and PhysX-error flags.

A contact-report header alone is not contact. An exact table/finger pair counts
only when its minimum signed separation is no greater than `0.5 mm`. This
admits a near-touching contact generated by the solver but rejects the observed
`10.6 mm` proximity candidate.

A finger fails the tabletop gate when any directly transformed vertex within
the table's local XY footprint is more than `0.5 mm` below the local tabletop
top plane. The test converts points into table-local coordinates, so the rule
does not assume an axis-aligned or origin-centered table. The old bottom-plane
rule and live `BBoxCache` values remain available only as diagnostic telemetry;
they cannot contribute to `PASS`.

The visual and collision supplier-CAD meshes must have matching topology and
world positions within `0.1 mm`. A mismatch fails closed because a collision
hold would not prove the visible finger is held.

### 2. Native Inspector validation process

Before the user-facing handoff, a dedicated temporary Isaac Sim Full process
opens the frozen Stage and enables `omni.physx.supportui`. It binds Physics
Inspector to:

- `/World/follower_left/vx300s_left/root_joint`;
- `/World/environment/worldBody/user_confirmed_table`.

It uses the same options as manual operation: Joint Drive target control,
quasistatic mode enabled, fixed articulation base, and gravity disabled. The
shoulder target change is issued through the same USD `ChangeProperty` command
observed by native `InspectorSimulation`, not through a direct link transform,
articulation teleport, or ordinary timeline playback. Native Inspector then
runs its fixed three-second authoring simulation (`180` steps at `1/60 s`).

Contact reporting is installed in a temporary Session Layer before Inspector
parses the Stage. Each sample reads contact separations and directly transforms
the visual and collision mesh points. The process runs exactly three clean
trials, reopening the frozen Stage between trials. It records JSON, a bounded
log, and a verified close screenshot. Any single failure prevents handoff.

The validation process never saves the Stage. Its test target and resulting
posture are disposable and the process exits after writing evidence.

### 3. Clean Full-GUI handoff

Only after the native three-trial gate passes does a new Isaac Sim Full process
open the same frozen Stage for the user. The existing stable startup sequence
then selects Perspective view, creates the two Inspector panels, binds the
exact articulation and table paths, verifies 13 joint rows and authoring state,
stops the timeline, and moves the window to workspace index 2.

Because validation and handoff use different processes, no test posture,
target value, anonymous layer, undo item, or dirty Inspector state can leak
into the manual session. The user-facing Stage must open from disk in its clean
initial posture and must not be saved.

## Rejected Alternatives

- **Correct only the standalone `World` verifier:** simpler, but it would not
  cover the native authoring scene used by the user's Inspector slider.
- **Run the test and handoff in the same dirty Stage:** faster, but discarding
  Inspector authoring state and undo history would be harder to prove.
- **Increase table thickness, collision offsets, friction, gains, or solver
  force:** these changes could conceal a bad gate and would alter the approved
  physical model.

## Failure Handling

The workflow fails closed and does not launch a clean handoff when:

- the Stage path, hash, root prim, sublayers, units, up-axis, articulation, or
  table identity differs from the frozen contract;
- native Inspector cannot enter and remain in authoring mode;
- fewer than 13 left joint rows are exposed;
- the contact is only a positive-separation proximity candidate;
- a directly transformed finger vertex enters more than `0.5 mm` below the
  tabletop within its local XY footprint;
- visual and collision finger vertices differ by more than `0.1 mm`;
- the infeasible shoulder target is not blocked, contact is not persistent,
  a disallowed support contact appears, or any state is non-finite;
- a PhysX, USD, rendering, or out-of-memory error invalidates a trial;
- the Stage hash changes after the disposable test process exits.

Failures retain artifacts and an explicit reason. They do not trigger a
tolerance, gain, geometry, or material sweep.

## Test-Driven Implementation

Implementation follows red-green-refactor in this order:

1. Add pure failing tests proving that a `10.6 mm` separation header is not
   contact and that a finger `1 mm` below the top surface fails even though it
   has not crossed the table bottom.
2. Add failing tests for table-local XY/top-plane conversion and direct
   visual/collision vertex correspondence.
3. Replace the old pure decision fields and bottom-plane acceptance with the
   minimum implementation required by those tests.
4. Replace live BBox acceptance in the runtime sampler with directly
   transformed mesh points and signed contact separation.
5. Add static startup contracts for the dedicated native Inspector validation
   process and its clean-process handoff boundary.
6. Implement the disposable Full native-Inspector runner and run three trials.
7. Launch a fresh user-facing Full instance only after the native report is
   `PASS`.

Focused unit tests run with the project environment. Isaac runtime tests use
the pinned Isaac Sim 5.1 installation and store high-output logs under
`.codex/artifacts/`. No test touches real ALOHA hardware.

Completion requires fresh evidence for all of the following:

- red tests fail for the intended old behavior, then pass after the fix;

- the runtime report contains exactly three native Inspector trial passes;

- a final screenshot is visually inspected before the user receives control;
