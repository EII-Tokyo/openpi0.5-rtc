# B200 / H100 / RTX 5090 四路 448 推理对比

日期：2026-09-16。

## 结论

在当前同一套 JAX 0.5.3 模型实现里，B200 是三台机器中最快的，但单样本 GPU 驻留模型调用相对 H100 仅快约 1.12×（普通）/1.10×（RTC）。
包含预处理和输出处理的完整 policy.infer，B200 普通 115.33 ms、RTC 159.76 ms；完整 RTC 相对 H100 约 1.28×，相对 5090 约 1.63×。
大 batch 更能体现差距：batch 8 普通/RTC 相对 H100 为 1.34×/1.29×。
这些是当前代码与机器配置的实测，不是 B200 理论硬件上限，也不能据此断言某张 GPU 的纯计算能力已经耗尽。

## 权重与测试设置

- 配置：`eii_data_system_with_rinse_cam4_fullft_h200_from_april_original_30repo`。
- 实验：`rinse_cam4_april_30repo_44entries_448_bs64_ga4_scan_nw96_fsdp4_fd65536_20260915`，3000 步。
- 权重直接从东京 S3 `openpi-tokyo` 下载到 B200，没有从本地或 103 上传权重。
- 103 上的 AWS 凭据仅用于生成临时签名 URL，没有复制到 B200；签名 URL 未保存到报告或 manifest。
- 下载 params/assets 共 19 个文件、12,443,883,411 字节，约 20 秒完成传输，随后逐文件 SHA256 校验全部通过；不含 train state。
- 四路实际输入均为 448×448，每路 1024 个视觉 token，文本长度 200，总 prefix 4296。完整调用中四路 image mask 均为 true。
- action horizon 50，去噪 10 步。RTC 使用 replan_start_step=25、handoff_delay_steps=10。
- 固定种子的合成图片和状态，prompt 为 `twist off the bottle cap and rinse the bottle`，subtask 为 `good action`；不连接机械臂，不评价动作质量。
- GPU 驻留输入：每组独立进程，预热 3 次，随后计时 30 次，显式等待输出完成并检查有限值。
- 完整 policy.infer：预热三条部署路径，额外丢弃每种模式前 5 次，然后计时 100 次。
- 未修改模型算法、分辨率或计算精度。基准脚本只增加了路径/标签参数。

## 显存、功耗与结束状态

全部 batch 及完整调用成功，无 OOM，输出有限值检查通过。

相应功耗采样最大值为 800.98/799.17/884.95/922.71 W；采样覆盖加载、编译、预热及测量，不能作为正式计时区间的平均功耗。
完整 policy.infer 最终显存为 17128 MiB；JAX 内存池约 17.19 GB，活跃分配峰值约 8.22 GB。
batch 8 内存池约 34.37 GB，活跃分配峰值约 16.63 GB。显存池大小不等于模型权重或实际活跃 tensor 的大小。
测试结束后全部测试进程退出，B200 无 GPU 计算进程，显存回到 0 MiB。机器保持开机，环境与权重保留。
