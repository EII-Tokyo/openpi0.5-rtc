## 2. 内容问题与修订决定

| 历史内容 | 问题 | 新版决定 |
|---|---|---|
| 把 Rinse/RLT 链路放在摘要中心 | 偏离“随机取瓶—拧盖—瓶身/瓶盖分类投放”的年度成果主线 | 降为“进一步研究”章节；基础 VLA 能力成为主线 |
| 把 835 个 RLT episode 写入摘要 | 容易让读者误认为是全部瓶子分拣基础训练数据 | 保留在 RLT 专项数据小节，并与 Hugging Face 基础训练数据分开统计 |
| 大量内部模型名称、源码位置和函数名 | 验收专家难以理解，违反公开报告术语约束 | 正文改成通俗功能语言；内部位置只进入证据矩阵 |
| 137/835 正奖励比例 | 是人工标签分布，不是真机成功率 | 保留为数据标签统计，并在图上直接写“不是成功率” |
| round 28–32 离线曲线 | 可以证明 RLT 训练实际运行，但不能证明基础分拣能力 | 保留为研究工作量证据，不放在“当前最好成果”主图 |
| 一条成功和一条失败关键帧 | 样本过少且不是现场演示录像 | 改为“训练/研究数据案例”；不能证明连续 1 小时运行 |
| “证据不足，尚不具备稳定演示条件” | 与用户提供的现场观察不一致，但现场观察也缺少正式记录 | 改为两层结论：现场已观察到长时间演示；统计验收仍缺录像和计数表 |
| 四相机、14 维状态和动作 | 有代码与数据证据 | 保留，但正文用“多视角视觉、双臂关节与夹爪状态”解释 |
| RLT actor/critic 细节公式 | 对年度验收主线过深 | 移至研究附录或用一页通俗流程说明 |
| 未来计划以自动判定和 RLT 为主 | 缺少下一年度插水管清洗目标 | 重排为基础模型、失败修复、标准评估、毫米级插入和强化学习 |

## 3. 新版必须新增的证据

1. ALOHA 正式设备照片 `aloha-home.jpg`，明确标注为静止/sleep 状态；
2. 数据采集软件的真实界面或功能证据；
3. 数据编辑中心的当前可见视口截图；
4. Hugging Face Dataset Viewer 的当前可见数据网格截图；
5. 基础瓶子任务数据仓库数量、唯一仓库数量、episode、frame 和采样权重；
6. 正式基础 VLA Checkpoint 与实际真机加载记录；
7. 基础训练 loss 与不同 Checkpoint 对比；
8. 有盖/无盖、正放/倒置、单瓶/多瓶等典型条件的成对证据；
9. 现场观察说明框：约 1 小时、约 2 个/分钟、无完整录像和计数表；
10. Attention 图；若不能从真实模型导出，则以缺失证据卡片代替。

## 4. 版式问题与修订决定

| 问题 | 历史证据 | 新版规则 |
|---|---|---|
| 频繁强制原地放图 | 13 个 `[H]` 浮动体 | 普通图采用页顶/页底浮动；章节边界再限制 |
| 单图过大、正文不足 | 页面总览多处可见 | 普通单图高度不超过正文区约 42% |
| 图表解释过短 | 多数图只有一行图注 | 每图增加“一句话看懂、专业读法、能说明、不能说明” |
| 图表风格偏默认 | 柱形、折线和 TikZ 风格不统一 | 建立统一色盲友好样式、字体和线宽 |
| 数据表数量不足 | 仅 1 个独立表文件 | 增加硬件、软件、数据、模型、实验、失败和计划表 |
| 缺少管理层总览 | 摘要直接进入算法细节 | 新增一页成果总览、工作量总览和证据等级 |

## 5. 事实边界

- “连续工作超过约 1 小时”和“平均约 2 个瓶子/分钟”来自现场展示观察，没有完整录像、逐瓶计数表和标准测试记录。
- 现场观察可以支持“已出现长流程连续工作能力”，不能支持带置信区间的稳定产能结论。
- Hugging Face 配置中出现的仓库是候选训练数据源；只有与实际运行日志或 Checkpoint 对应后，才能称为某次正式训练的真实输入。
- RLT 数据、模型和曲线证明团队开展了强化学习研究，不能替代基础 VLA 分拣任务的真机成功率。
- Attention 只能称为模型关注线索，不能称为因果解释。
- 无现场完整视频，因此新版固定为“无演示视频版本”。
